# UI/UX Portfolio QA Checklist

## Visual
- [ ] Hero hierarchy is clear at desktop and mobile widths
- [ ] Project cards have consistent spacing and metadata
- [ ] Case-study pages use the same visual language
- [ ] Design-system page documents reusable foundations

## UX
- [ ] Primary navigation reaches Work, Process, Systems, Preview, About, Contact
- [ ] Every selected project has a case-study route
- [ ] Case studies distinguish planned research/testing from completed evidence
- [ ] No unsupported user research results are presented as facts

## Accessibility
- [ ] Semantic headings and landmarks are present
- [ ] Keyboard focus is visible
- [ ] Reduced-motion preference is respected
- [ ] Link labels describe their destination
- [ ] Information is not communicated by color alone

## Privacy and security
- [ ] No API keys, tokens, passwords, or private credentials
- [ ] No unnecessary personal-data collection
- [ ] Future API credentials remain server-side
- [ ] Third-party dependencies are minimized and reviewed

## Deployment
- [ ] Deploy from the uiux-portfolio branch
- [ ] Configure deployment root as uiux when using the static portfolio directly
- [ ] Verify the final HTTPS URL
- [ ] Replace the temporary source QR target with the verified live URL
- [ ] Test direct loading of every case-study page

## Final acceptance
The portfolio should communicate UX thinking through evidence and process, not claim experience or research that has not actually been completed.
